Variant filtering

Convert a permissive raw SNP callset into a transparent, quality-controlled population-genomic dataset by restricting variant type, masking unreliable genotypes, evaluating sample-level missingness, recalculating allele statistics, controlling site missingness and applying an analysis-appropriate minor-allele-frequency threshold.

Objective

The raw VCF produced during SNP calling is deliberately inclusive. It preserves candidate SNPs and genotype evidence so that filtering decisions can be made explicitly rather than hidden inside the discovery step. Variant filtering therefore operates at three different levels: the genotype, the sample and the site.

raw multi-sample SNP VCF
        ↓
retain biallelic SNPs
        ↓
mask low-quality genotypes
        ↓
evaluate missingness by sample
        ↓
define a core sample set
        ↓
recalculate AC / AN / AF / MAF / F_MISSING
        ↓
filter sites with excessive missingness
        ↓
apply MAF threshold
        ↓
quality-controlled SNP dataset
        ↓
independent-SNP selection
Filtering is an analysis design decision

The thresholds shown here are the settings validated for this tutorial workflow: genotype depth ≥3, genotype quality ≥20, site missingness ≤20% and MAF ≥0.05. They are defensible starting points for this type of UCE population dataset, but they are not universal constants. Sequencing depth, sample size, taxonomic divergence and the downstream question should always be considered.

1. Three levels of filtering

LevelQuestionAction in this module
GenotypeIs this individual genotype supported by enough read evidence and confidence?Convert low-DP or low-GQ genotypes to missing (./.).
SampleDoes an individual remain poorly represented across the dataset?Evaluate per-sample missingness and define a core sample set when necessary.
SiteIs a SNP sufficiently complete and informative across the retained samples?Filter by missingness and minor allele frequency.

Keeping these three levels separate makes the workflow easier to interpret and prevents a low-quality genotype in one sample from automatically deleting an otherwise useful SNP for every other individual.

2. Input

The starting point is the SNP-only VCF generated in the previous module. The example below assumes that the biologically appropriate population sample set was already selected before joint SNP calling.

04_snp_calling/
├── raw_snps.vcf.gz
├── raw_snps.vcf.gz.csi
└── samples.txt

The VCF should contain GT, DP, AD and GQ FORMAT fields, because genotype-level filtering depends on the evidence retained during calling.

3. Activate the existing environment

conda activate uce-popgen

Define portable project paths:

PROJECT="/path/to/project"
POPGEN="$PROJECT/population_genomics"
SNP_CALLING="$POPGEN/04_snp_calling"
RAW_SNPS="$SNP_CALLING/raw_snps.vcf.gz"
SAMPLES="$SNP_CALLING/samples.txt"

4. Record the starting dataset

Before changing the VCF, record the number of samples and SNP records. This baseline is useful for reporting the filtering cascade later.

bcftools query -l "$RAW_SNPS" | wc -l
bcftools index -n "$RAW_SNPS"

Also keep the original VCF unchanged. Every filtering step in this tutorial writes to a new file.

Never overwrite the raw callset

A filtering threshold may later be revised. Preserving the unmodified raw SNP VCF makes every alternative filtering strategy reproducible without repeating the expensive joint calling step.

5. Retain only biallelic SNPs

Population-structure tools generally operate most cleanly on variants with one reference and one alternate allele. Restricting the dataset to biallelic SNPs also avoids carrying multiallelic encoding into later genotype and allele-frequency filters.

bcftools view \
  -m2 -M2 \
  -v snps \
  -Oz \
  -o "$SNP_CALLING/biallelic_snps.vcf.gz" \
  "$RAW_SNPS"

bcftools index "$SNP_CALLING/biallelic_snps.vcf.gz"
bcftools index -n "$SNP_CALLING/biallelic_snps.vcf.gz"
-m2
Require at least two alleles at a retained record.
-M2
Allow no more than two alleles: REF + one ALT.
-v snps
Restrict records to SNPs.
-Oz
Write a BGZF-compressed VCF suitable for indexing.

6. Mask low-quality genotypes instead of deleting whole sites

A SNP may be well supported in most individuals but poorly covered in one or two samples. Removing the complete site would discard useful information. Instead, low-quality genotypes are converted to missing while the site remains available to the other samples.

The validated tutorial thresholds are:

DP ≥ 3

Require at least three high-quality bases supporting the genotype evaluation.

GQ ≥ 20

Require a Phred-scaled genotype quality of at least 20.

Genotypes failing either criterion are set to missing:

bcftools +setGT \
  "$SNP_CALLING/biallelic_snps.vcf.gz" \
  -Oz \
  -o "$SNP_CALLING/biallelic_DP3_GQ20.vcf.gz" \
  -- \
  -t q \
  -n . \
  -i 'FMT/DP<3 | FMT/GQ<20'

bcftools index "$SNP_CALLING/biallelic_DP3_GQ20.vcf.gz"

The number of VCF records should normally remain unchanged here because genotypes are being masked, not sites removed.

bcftools index -n "$SNP_CALLING/biallelic_DP3_GQ20.vcf.gz"

7. The single | is important

BCFtools distinguishes sample-wise logic from record-wise logic when FORMAT fields are evaluated across multiple samples. For genotype masking in this workflow, the expression uses a single vertical bar:

-i 'FMT/DP<3 | FMT/GQ<20'

This targets genotypes meeting either low-quality condition. Using the record-level OR operator in the wrong context can select an entire site because one sample satisfies the expression and may therefore mask far more genotypes than intended.

Validate after every genotype-editing command

Always calculate per-sample missingness after +setGT. Identical or implausibly extreme missingness across every individual is a warning that the filter expression should be inspected before continuing.

8. Calculate per-sample missingness

Genotype filtering should be followed by sample-level diagnostics. bcftools stats -s - produces per-sample statistics in PSC records.

bcftools stats \
  -s - \
  "$SNP_CALLING/biallelic_DP3_GQ20.vcf.gz" \
  > "$SNP_CALLING/biallelic_DP3_GQ20.per_sample.stats.txt"

The following summary was used in the validated workflow. Inspect the PSC layout produced by your installed BCFtools version before adapting column numbers.

awk -F'	' '
BEGIN {
    OFS="	"
    print "sample","nRefHom","nNonRefHom","nHets","avg_depth","nMissing","missing_percent"
}
$1=="PSC" {
    total=$4+$5+$6+$14
    pct=(total>0 ? 100*$14/total : 0)

    printf "%s	%d	%d	%d	%.2f	%d	%.2f
", \
        $3,$4,$5,$6,$10,$14,pct
}' \
"$SNP_CALLING/biallelic_DP3_GQ20.per_sample.stats.txt" \
> "$SNP_CALLING/DP3_GQ20_missingness.tsv"

Sort from highest to lowest missingness:

{
    head -1 "$SNP_CALLING/DP3_GQ20_missingness.tsv"
    tail -n +2 "$SNP_CALLING/DP3_GQ20_missingness.tsv" \
      | sort -t $'	' -k7,7nr
} | column -t -s $'	'

9. Decide whether a core sample set is needed

Do not remove individuals from a single arbitrary percentage threshold. Compare genotype missingness with the mapping-QC results from the previous module and look for samples that are clearly separated from the main distribution.

A sample becomes a strong exclusion candidate when multiple lines of evidence agree, for example:

  • low mapping rate or low UCE breadth;
  • poor ≥3× or ≥5× coverage;
  • high raw genotype missingness;
  • very high missingness after DP/GQ masking;
  • a clear gap between the candidate sample and the main sample distribution.
Biological importance still matters

A low-coverage individual may represent a unique locality or lineage. Preserve the sample and its BAM even when it is excluded from the primary core dataset. A broader “extended” dataset can be retained for sensitivity analyses.

10. Define the core sample list

Record excluded samples explicitly rather than deleting files. Replace the example identifiers below with the samples identified by your own QC.

cat > "$SNP_CALLING/core_excluded_samples.txt" <<'EOF'
sample_lowcov_01
sample_lowcov_02
sample_lowcov_03
EOF

Create the retained core sample list from the sample set used for calling:

grep -v -F -x -f \
  "$SNP_CALLING/core_excluded_samples.txt" \
  "$SAMPLES" \
  > "$SNP_CALLING/core_samples.txt"

wc -l "$SNP_CALLING/core_samples.txt"

11. Subset samples before filtering site missingness

This order matters. If severely incomplete samples remain in the VCF while site missingness is calculated, many SNPs can be discarded solely because those few individuals lack coverage. Once a core sample set has been justified, remove the problematic samples first and then recalculate site-level statistics.

bcftools view \
  -S "$SNP_CALLING/core_samples.txt" \
  -Oz \
  -o "$SNP_CALLING/core_biallelic_DP3_GQ20.vcf.gz" \
  "$SNP_CALLING/biallelic_DP3_GQ20.vcf.gz"

bcftools index "$SNP_CALLING/core_biallelic_DP3_GQ20.vcf.gz"

bcftools query -l \
  "$SNP_CALLING/core_biallelic_DP3_GQ20.vcf.gz" \
  | wc -l

12. Recalculate allele and missingness tags

After changing genotypes or samples, allele-count and missingness annotations must describe the dataset that actually remains. Recalculate them with the BCFtools +fill-tags plugin.

bcftools +fill-tags \
  "$SNP_CALLING/core_biallelic_DP3_GQ20.vcf.gz" \
  -Oz \
  -o "$SNP_CALLING/core_biallelic_DP3_GQ20_tags.vcf.gz" \
  -- \
  -t AC,AN,AF,MAF,F_MISSING,NS

bcftools index "$SNP_CALLING/core_biallelic_DP3_GQ20_tags.vcf.gz"
AC
Alternate allele count among called genotypes.
AN
Total number of alleles represented by called genotypes.
AF
Allele frequency calculated from the retained genotypes.
MAF
Frequency of the second most common allele; for biallelic SNPs, the minor allele frequency.
F_MISSING
Fraction of samples with missing genotype at the site.
NS
Number of samples with genotype data at the site.

13. Filter site missingness

The validated workflow retains SNPs with no more than 20% missing genotypes:

bcftools view \
  -i 'F_MISSING<=0.20' \
  -Oz \
  -o "$SNP_CALLING/core_DP3_GQ20_miss20.vcf.gz" \
  "$SNP_CALLING/core_biallelic_DP3_GQ20_tags.vcf.gz"

bcftools index "$SNP_CALLING/core_DP3_GQ20_miss20.vcf.gz"
bcftools index -n "$SNP_CALLING/core_DP3_GQ20_miss20.vcf.gz"

With 34 retained diploid samples, for example, F_MISSING ≤ 0.20 permits at most six missing individuals at a site, because 7/34 exceeds 0.20. At least 28 individuals must therefore be called.

14. Recheck sample missingness after the site filter

Site filtering can markedly improve the effective completeness of the retained individuals. Recalculate sample-level missingness before deciding whether further samples should be removed.

bcftools stats \
  -s - \
  "$SNP_CALLING/core_DP3_GQ20_miss20.vcf.gz" \
  > "$SNP_CALLING/core_DP3_GQ20_miss20.per_sample.stats.txt"

Use the same PSC summary method as above to create an updated missingness table.

A core dataset should become more homogeneous

After removing clear sample outliers and filtering poorly represented sites, most individuals should cluster within a much narrower missingness range. If one sample remains dramatically separated from the rest, revisit its mapping and coverage metrics before continuing.

15. Why sample filtering can recover useful SNPs

Keeping extremely incomplete samples during a site-missingness filter can reduce the number of usable SNPs for every well-sequenced individual. In the validated tutorial dataset, applying the same 20% site-missingness criterion after defining the core sample set retained more SNPs than applying it while the three strongest sample outliers were still present.

This is not an argument for removing samples merely to maximize SNP count. It demonstrates why sample QC and site QC should be evaluated together and why the order of operations should be explicit.

16. Apply a minor allele frequency filter

For PCA, DAPC and model-based ancestry analyses, extremely rare variants can contribute noise, emphasize individual-specific errors and complicate interpretation. The validated workflow uses MAF ≥ 0.05.

bcftools view \
  -i 'MAF>=0.05' \
  -Oz \
  -o "$SNP_CALLING/core_DP3_GQ20_miss20_MAF05.vcf.gz" \
  "$SNP_CALLING/core_DP3_GQ20_miss20.vcf.gz"

bcftools index "$SNP_CALLING/core_DP3_GQ20_miss20_MAF05.vcf.gz"
bcftools index -n "$SNP_CALLING/core_DP3_GQ20_miss20_MAF05.vcf.gz"
MAF depends on the biological question

MAF ≥ 0.05 is appropriate for the population-structure branch developed here. Do not automatically apply the same threshold to analyses whose purpose is specifically to study rare variants, recent mutations or very small populations.

18. Core and extended datasets

Sample exclusion does not mean deleting the biological material or permanently abandoning the individual. Maintain explicit alternative datasets when low-coverage samples are biologically important.

core dataset
    high-completeness sample set
    → primary PCA / DAPC / ancestry analyses

extended dataset
    core + biologically important low-coverage samples
    → sensitivity analysis
    → test whether conclusions change when these individuals are retained

If the major structure signal is stable across core and extended analyses, confidence in the biological interpretation increases. If conclusions change substantially, the role of missing data should be investigated explicitly.

19. What is not done in this module

The final 28,383-SNP example dataset is quality filtered, but the SNPs are not yet independent. Multiple variants may occur within the same UCE locus and can therefore be physically linked.

quality-controlled SNP dataset
        ≠
independent-marker dataset

Do not move directly from this file to PCA, DAPC, ADMIXTURE or STRUCTURE without considering linkage or locus-level dependence. Independent-SNP selection is handled in the next module.

21. Common mistakes

ProblemWhy it mattersRecommended response
Filtering sites before masking poor genotypesA weak genotype can make a site appear more complete or reliable than it is.Mask genotype-level failures first.
Using record-level logic accidentally in +setGTOne failing sample can trigger changes across an entire site.Validate the expression and inspect per-sample missingness immediately.
Removing samples only because they have the largest missingnessA ranking alone does not define a biologically meaningful threshold.Combine genotype missingness with mapping breadth, depth and study design.
Calculating MAF before changing the sample set and never updating itAllele counts and frequencies may refer to individuals no longer present.Recalculate tags after genotype masking and sample subsetting.
Applying F_MISSING before removing severe sample outliersGood SNPs can be lost because a few incomplete samples lack coverage.Define the justified core sample set first, then recalculate site missingness.
Treating MAF 0.05 as universalRare-variant analyses have different goals.Choose MAF according to the downstream question.
Overwriting intermediate VCFsThreshold comparisons become difficult to reproduce.Write a new, descriptively named file at every filtering stage.

22. Validation checklist

✓ The raw SNP VCF was preserved unchanged.
✓ Only biallelic SNP records were retained.
✓ Genotypes with DP < 3 or GQ < 20 were converted to missing.
✓ Per-sample missingness was evaluated after genotype masking.
✓ Sample exclusions were justified using multiple QC metrics and recorded in a text file.
✓ The core sample subset was created before applying site missingness.
✓ AC, AN, AF, MAF, F_MISSING and NS were recalculated for the retained genotypes and samples.
✓ Sites with more than 20% missing genotypes were removed.
✓ Per-sample missingness was checked again after site filtering.
✓ MAF ≥ 0.05 was applied only after the core dataset was defined.
✓ The final filtered VCF is compressed, indexed and retains the expected sample set.
✓ Low-coverage but biologically important samples were preserved for possible sensitivity analyses.

23. Final output

The principal output of this module is the quality-controlled, frequency-filtered SNP VCF:

$SNP_CALLING/core_DP3_GQ20_miss20_MAF05.vcf.gz

This file is appropriate as the input to independent-marker selection, but it is not yet the final input for population-structure analyses because multiple SNPs can still occur within individual UCE loci.
