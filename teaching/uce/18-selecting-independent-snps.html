Selecting independent SNPs

Reduce locus-level dependence in a filtered UCE SNP dataset by selecting one reproducible SNP from each informative UCE locus. The resulting marker set is intentionally conservative and is suitable for downstream population-structure analyses such as PCA, DAPC and ancestry inference.

Objective

After variant filtering, a UCE dataset can still contain many SNPs from the same captured locus. Treating every one of those variants as an independent marker gives highly variable loci more weight than loci containing only a few SNPs and may violate assumptions made by downstream structure analyses.

quality-controlled SNP dataset
        ↓
many SNPs can occur within the same UCE
        ↓
identify informative UCE loci
        ↓
choose one SNP from each locus
        ↓
approximately independent marker dataset
        ↓
PCA / DAPC / ancestry analyses
One SNP per UCE is conservative, not magical

Choosing one SNP per UCE removes within-locus clustering of variants and prevents highly polymorphic loci from dominating the analysis. It does not prove that all retained markers are in complete linkage equilibrium, because different UCE loci can still show biological or statistical association. The strategy is therefore best described as reducing locus-level dependence.

2. Why not use all filtered SNPs directly?

UCE capture targets hundreds to thousands of discrete loci. A single UCE may contain one SNP, while another may contain dozens. In the validated dataset, the most variable loci contained more than 50 SNPs and one locus contained more than 80.

Using all SNPsOne SNP per UCE
Highly variable loci contribute many correlated markers.Every informative UCE contributes exactly one marker.
Some genomic regions receive disproportionate weight.Locus representation is balanced.
Within-locus linkage can influence ordination and ancestry models.Within-UCE SNP clustering is removed.
Best retained for analyses that explicitly model or tolerate linkage.Simple and transparent for exploratory population structure.

3. Count informative UCE loci

Each UCE locus is represented by the VCF chromosome/contig identifier in CHROM. Count the number of distinct UCE identifiers that still contain at least one filtered SNP:

bcftools query \

  "$FILTERED_VCF" \
  | sort -u \
  | wc -l

4. Inspect SNP density among loci

Before subsampling, inspect how unevenly SNPs are distributed among UCEs:

bcftools query \
  -f '%CHROM\n' \
  "$FILTERED_VCF" \
  | sort \
  | uniq -c \
  | sort -nr \
  | head -20

Large counts at the top of this list demonstrate why treating every filtered SNP as an equally independent observation can overweight a subset of highly polymorphic UCEs.

6. Randomly select one SNP per UCE

For every UCE locus, randomly select one of its retained SNPs. A fixed random seed makes the selection fully reproducible: rerunning the script with the same candidate list and seed returns the same marker set.

python3 - \
  "$SNP_CALLING/core_34_all_snp_positions.tsv" \
  "$SNP_CALLING/core_34_one_snp_per_uce.regions" <<'PY'
import sys
import random
from collections import defaultdict

input_file = sys.argv[1]
output_file = sys.argv[2]

# Fixed seed for reproducibility.
random.seed(20261004)

loci = defaultdict(list)

with open(input_file) as f:
    for line in f:
        chrom, pos = line.rstrip().split("\t")
        loci[chrom].append(int(pos))

with open(output_file, "w") as out:
    for chrom in sorted(loci):
        pos = random.choice(loci[chrom])
        out.write(f"{chrom}\t{pos}\t{pos}\n")

print(f"Selected {len(loci)} SNPs from {len(loci)} UCE loci.")
PY
Why use a fixed seed?

Random selection avoids systematically favoring the most common, highest-frequency or most extreme SNP within each UCE. The fixed seed preserves that neutrality while making the exact result repeatable and auditable.

7. Why not always choose the highest-MAF SNP?

Selecting the highest-MAF SNP from each locus can be useful for some purposes, but it deliberately enriches the marker set for common variation. For an exploratory structure dataset, that choice can introduce a systematic ascertainment preference.

The workflow used here instead asks a simpler question: after the quality filters have already been applied, which one of the acceptable SNPs from each UCE should represent that locus? Random selection with a fixed seed provides a transparent answer without ranking SNPs by allele frequency.

8. Validate the regions file

The number of lines in the regions file should equal the number of informative UCE loci:

wc -l "$SNP_CALLING/core_34_one_snp_per_uce.regions"

For the validated example:

1546 core_34_one_snp_per_uce.regions

Each line contains:

CHROM    START    END

with START = END, because each interval represents exactly one SNP position.

12. One-SNP-per-UCE versus LD pruning

One-SNP-per-UCE and statistical LD pruning solve related but different problems.

ApproachStrengthLimitation
One SNP per UCEDirectly removes multiple markers from the same captured locus and is easy to reproduce.Does not test LD between different UCE loci.
LD pruningUses observed genotype correlations to remove markers exceeding a chosen LD threshold.Requires a window/r² strategy and can be harder to interpret for disconnected target-capture loci.

For UCE target-capture data, one SNP per locus is a transparent conservative default. LD pruning can be added later as a sensitivity analysis when biological linkage among loci or dense genomic coordinates are available.

13. Reproducibility considerations

Three details determine whether another analyst can reproduce the exact marker set:

✓ Preserve the filtered VCF used as the candidate pool.
✓ Record the exact fixed random seed.
✓ Preserve the generated .regions file together with the final VCF.

If the candidate SNP dataset changes because a filter threshold changes, the one-SNP-per-UCE selection should be regenerated from that new candidate pool even when the same random seed is retained.

15. Common mistakes

ProblemWhy it mattersRecommended response
Selecting independent SNPs before quality filteringA randomly chosen SNP may later fail DP, missingness or MAF filters, leaving loci unevenly represented.Perform one-SNP-per-UCE selection after the final quality filters.
Using a random choice without a recorded seedThe exact marker set changes between runs.Use and document a fixed seed.
Choosing the highest-MAF SNP without stating itThe dataset is systematically enriched for common variants.State the selection rule explicitly or use reproducible random selection.
Assuming one SNP per UCE means complete linkage equilibriumAssociation can still exist between distinct UCE loci.Describe the set as approximately independent and consider LD sensitivity analyses if needed.
Failing to validate the final locus countDuplicated or mismatched region records can silently retain multiple SNPs from a locus.Confirm that every CHROM occurs exactly once.

16. Validation checklist

✓ The input VCF is the final quality-controlled dataset from variant filtering.
✓ The number of informative UCE loci was counted before SNP selection.
✓ Candidate SNP positions were exported from the filtered VCF.
✓ Exactly one SNP was selected per UCE locus.
✓ A fixed random seed was recorded.
✓ The regions file contains one line per retained UCE.
✓ The final VCF contains the expected number of samples.
✓ The final VCF contains the expected number of SNPs.
✓ Every UCE identifier occurs exactly once in the final VCF.
